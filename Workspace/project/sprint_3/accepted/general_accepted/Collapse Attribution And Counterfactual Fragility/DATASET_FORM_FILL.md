## Overview

This dataset is a fully synthetic, self-generated corpus of rigid-body block-stack scenes. Each scene is a small tower of coloured boxes resting on a flat ground plane, captured as a single rendered RGB still at the instant before the stack is released under gravity. The towers are procedurally built with small horizontal jitter so that many of them sit close to their stability boundary.

Every scene carries physics-derived outcome labels obtained by running a deterministic rigid-body simulation: whether the stack moves once released, which block moves first, and a counterfactual analysis of which single block, if removed, would most change the outcome. The geometry is procedurally generated (axis-aligned boxes) — no external 3D assets are used.

## File Structure

```
images/
├── <scene_hash>.png        one RGB still per scene
scenes.csv                  one row per scene (outcome labels)
blocks.csv                  one row per (scene, block)
```

`scene_hash` is a 16-hex-character content id; each `images/<scene_hash>.png` has a matching row in `scenes.csv` and one or more rows in `blocks.csv`. With the default generation settings the corpus contains exactly 3,000 images, 3,000 rows in `scenes.csv` (one per scene), and 16,431 rows in `blocks.csv` (one per block across all scenes).

## Features

**`scenes.csv`**

| Column                  | Type | Description              |
|-------------------------|------|--------------------------|
| `scene_hash`            | str  | 16-hex scene id          |
| `n_blocks`              | int  | Blocks in the scene      |
| `will_collapse`         | int  | 1 if stack moves         |
| `initiator_block_id`    | int  | First mover (-1 = none)  |
| `keystone_block_id`     | int  | Top keystone (-1 = none) |
| `keystone_alt_block_id` | int  | 2nd keystone (-1 = none) |

**`blocks.csv`**

| Column       | Type | Description              |
|--------------|------|--------------------------|
| `scene_hash` | str  | Scene id                 |
| `block_id`   | int  | Block id within scene    |
| `cx`         | int  | Block centroid x (pixel) |
| `cy`         | int  | Block centroid y (pixel) |
| `color_r`    | int  | Block colour R (0-255)   |
| `color_g`    | int  | Block colour G (0-255)   |
| `color_b`    | int  | Block colour B (0-255)   |

**Per image**

| Property   | Value                  |
|------------|------------------------|
| Format     | PNG (RGB, 3 channels)  |
| Dimensions | 256 × 256 px (default) |
| Content    | One block-stack still  |

## Notes

* Fully synthetic — no real-world imagery, no personal data, no third-party assets. Geometry is procedural axis-aligned boxes; colours come from a fixed palette.
* Generation is deterministic: each scene is seeded from a fixed base seed and its scene index, so the corpus is exactly reproducible from the generation script.
* `initiator_block_id` and the keystone columns use `-1` to denote "none" (e.g. a stable stack has no initiator).
* Default generation settings produce exactly 3,000 scenes (3,000 images, 16,431 block rows) at 256×256 px — a small corpus (~4.5 MB packaged), well under the platform upload budget.
