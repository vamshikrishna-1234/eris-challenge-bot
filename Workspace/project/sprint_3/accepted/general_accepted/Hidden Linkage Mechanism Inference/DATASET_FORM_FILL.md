## Description

## Overview

This dataset is a fully synthetic, self-generated corpus of short videos of a board of colour-coded spinning rotors. Each clip is rendered from one fixed oblique camera looking down at a flat board on which several short discs (rotors) sit, each painted a distinct colour and carrying a dark radial tick mark so that its rotation is visible. No physical couplings are drawn between rotors: the drive linkage is hidden. One or two source rotors turn under their own distinctive, smoothly time-varying speed signature; a driven rotor reproduces its driver's signature scaled and lagged and passes its motion onward, while decoy rotors spin on independent schedules. The clips are produced by a small dependency-free software 3D projector (NumPy + Pillow) and muxed to H.264 with imageio; no external 3D assets, simulators, or real imagery are used.

Every clip carries exact labels because each scene is built from a sampled coupling forest and source profiles before it is rendered: the rotor colour-ids present, the directed drive graph (driver -> driven), which rotors are still rotating in the final frame, and which rotor moves first. Each base scenario is also rendered as deterministic variants (a relit version and a horizontally mirrored version); rotor identity is colour-coded, so the labels are unchanged across variants.

## File Structure

```
videos/
├── <scene_hash>.mp4        one rotor-board clip per row
scenes.csv                  one row per clip (inputs + labels + metadata tags)
```

`scene_hash` is a 16-hex-character content id; each `videos/<scene_hash>.mp4` has exactly one matching row in `scenes.csv`.

## Features

Each row of `scenes.csv` describes exactly one rendered clip, with these columns:

* `scene_hash` (str): 16-hex-character content id of the clip.
* `video` (str): relative path to the clip's mp4 (`videos/<scene_hash>.mp4`).
* `base_scenario_id` (str): id shared by every variant of the same scenario.
* `variant` (str): which rendered variant of the scenario — one of `base`, `relight`, or `mirror`.
* `num_rotors` (int): number of rotors present on the board in the clip.
* `rotors` (str): JSON list of the rotor colour-ids present (e.g. `["red", "blue", "green"]`).
* `topology_family` (str): tag for the coupling-topology family of the scenario.
* `board_style` (str): tag for the lighting / board style of the render.
* `edges_json` (str): JSON list of directed `[driver, driven]` colour-id pairs giving the hidden drive linkage.
* `moving_at_end_json` (str): JSON list of rotor colour-ids still rotating in the final frame.
* `first_mover` (str): colour-id of the rotor that begins rotating first.

Each `videos/<scene_hash>.mp4` is a single rotor-board clip encoded as H.264 MP4, 640 x 384 px, 96 frames at 12 FPS.

## Notes

* Fully synthetic — no real-world imagery, no personal data, no third-party assets. Geometry is procedural prisms and boxes on a plane; colours come from a fixed palette.
* Generation is deterministic: each base scenario is seeded from a fixed base seed and its index, so the corpus is exactly reproducible from the generation script, which is provided alongside the data.
* Rotor identity is colour-coded and therefore mirror-safe; horizontally flipped variants carry the same colour-id labels, with only the on-screen layout and apparent spin direction reversed.
* Default generation settings produce a few hundred clips at 640 x 384 px, a small corpus of roughly a hundred megabytes — well under the platform upload budget.
