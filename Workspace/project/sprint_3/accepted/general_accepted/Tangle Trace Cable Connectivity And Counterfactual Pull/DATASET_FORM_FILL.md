# Dataset creation form — fill-in

## Dataset name

```
Synthetic Cable-Tangle Board Renders With Connectivity And Pull Labels
```

## Overview

A self-rendered corpus of cable-board images showing visually distinct labelled cables running from top endpoints (T0, T1, ...) down through a central tangle to bottom endpoints (X0, X1, ...). Scenes include varied cable palettes, endpoint marker shapes, textured board backgrounds, shadows, mild camera jitter, and distractor cable scraps; at every real crossing one cable visibly passes over and occludes the other. Each image ships with exact labels: which top endpoint connects to which bottom endpoint (with an "unknown" flag for cables buried too deep in the dense core to trace), the number of genuine pairwise interlocks, and two pull-counterfactual fields (whether pulling a named endpoint locks or slips, and the ordered list of cables it drags taut), plus metadata tags. The tangles are constructed as braids (stacks of adjacent swaps) so that all connectivity, every over/under, and therefore the full pull behaviour are exact by construction. All geometry and rendering are procedurally generated with a small NumPy + Pillow software renderer; there are no external assets.

## File structure

```
images/<scene_hash>.jpg   one rendered cable-board image per row of scenes.csv
scenes.csv                one row per image: inputs, labels, and metadata tags
```

* `images/` holds the colour JPEG cable-board renders, each `640 x 480`.
* `scenes.csv` has one row per image.

## scenes.csv columns

Each row of `scenes.csv` describes exactly one rendered image, with these columns:

| Column              | Type   | Description                                                       |
|---------------------|--------|-------------------------------------------------------------------|
| `scene_hash`        | string | Stable per-image hash; matches the jpg filename                   |
| `image`             | string | Relative path to the image (`images/<scene_hash>.jpg`)           |
| `base_scenario_id`  | string | Id of the underlying scenario, shared by its variants            |
| `variant`           | string | Render variant: `base` or `recolor`                              |
| `render_style`      | string | Board style tag: `light` or `dark`                               |
| `n_cables`          | int    | Number of cables (4-6)                                           |
| `pull_endpoint`     | string | Top endpoint the pull counterfactual acts on (e.g. `T2`)        |
| `pairing_json`      | string | JSON object: each top endpoint -> its bottom endpoint or `"unknown"` |
| `n_true_locks`      | int    | Number of genuine pairwise interlocks (clasps)                  |
| `pull_outcome`      | string | `locks`, `slips`, or `unknown` (buried pulled cable)            |
| `pull_taut_json`    | string | JSON list of cables dragged taut, in tension order              |
| `tangle_family`     | string | Cable-count family tag (e.g. `n4`, `n5`, `n6`)                  |
| `ood_axis`          | string | Scene-difficulty tag (standard / buried_query / many_cables)     |

`pairing_json` keys are the top endpoints `T0..`; values are bottom endpoints `X0..` or the string `"unknown"` for cables buried too deep to trace. `pull_taut_json` lists cables by their top endpoint, in the order tension reaches them, and is empty when nothing is dragged. All fields are ground truth derived from the exact braid construction; they are not measured off pixels.

## Source

Fully synthetic. Generated by a self-contained Python script that samples each tangle deterministically as a braid (a stack of adjacent over/under swaps), derives the connectivity, interlocks, and pull behaviour in closed form, and renders the cable-board image with a dependency-free software renderer (NumPy + Pillow). No external datasets, models, or assets are used.

## Notes

* Defaults yield roughly 2,000 images (about 1,000 base scenarios x 2 variants), totalling well under the multi-GB upload budget.
* Each base scenario is paired with two deterministic rendered variants (`base` and `recolor`) using different style families; the two variants re-sample independent tangles, so they do not share labels.
* Cable counts, tangle families, and difficulty slices are balanced across the corpus; a sizeable share of images place the pulled cable, or some cables, in the dense core where they are genuinely untraceable and the correct answer is `unknown`.
